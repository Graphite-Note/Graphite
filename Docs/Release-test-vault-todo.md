# A vault to test every feature before a release: implementation TODO

Created: 2026-11-12.

Status: planned. Issues: [#162](https://github.com/Graphite-Note/Graphite/issues/162), [#164](https://github.com/Graphite-Note/Graphite/issues/164), [#163](https://github.com/Graphite-Note/Graphite/issues/163) and [#165](https://github.com/Graphite-Note/Graphite/issues/165), one per section.

## Request

The owner, 2026-11-12: "id like to have a vault or whatever on the repo used to test every feature so we can have proper tests before releases". In the same message they asked that the checks left for a device or their vault be made by the sessions themselves, in a simulator or on their iPad, rather than left for the owner.

Today the repository has `Tests/BaseSampleVault` (36 files: bases, places, books, three course notes) for the bases, and each test writes its own small vault. No vault shows every feature at once, and nothing runs every kind of note through every view before an upload.

## 1. The vault

Issue: [#162](https://github.com/Graphite-Note/Graphite/issues/162)

- [ ] `Tests/ReleaseVault/`, an Obsidian vault in the repository with a note or a file for every feature Graphite has, made up for the purpose (no person's notes, no photos of people, no audio or video files, so nothing can play a sound): Markdown and Obsidian syntax (headings, lists, tasks, quotes, code, footnotes, comments, HTML, highlights); links, embeds, block and heading references, aliases, unresolved links; properties of every type and nested tags; callouts (nested, folded, with tables and math); inline and display math, long formulas; tables (wide, with formulas, pictures and escaped pipes); pictures alone and side by side, with sizes; Mermaid diagrams of every type Graphite draws; bases (table, cards, list, map) and an embedded base; a canvas; PDFs (text, scanned page, annotated with ink, highlights and text boxes); a drawing; a notebook made by Graphite; a Goodnotes and a Notability sample from `Tests/SyntheticNotebooks`; daily notes over two months and templates; iframes pointing at the loopback test server only; places for the maps; a long lecture note for scrolling; a note for every core plugin that has its own syntax.
- [ ] A `README.md` in the vault that lists every note, what it shows and which feature and todo file it covers, so a new feature adds its note there.
- [ ] Small: the whole vault under 5 MB, pictures generated as small PNGs, PDFs generated by a script in `scripts/` so they can be made again.

## 2. An automated pass over the vault

Issue: [#164](https://github.com/Graphite-Note/Graphite/issues/164)

- [ ] A Mac package test and an iPad hosted test that open every note of the vault in Live Preview, the reading view and source mode, and every other file in its own view, and fail on an error, a crash, a block left as raw source where a view was expected, a picture that did not load, or a main-thread freeze over a set budget.
- [ ] Screenshots of every note in each view attached to the run (`XCTAttachment`, kept always), so a release candidate can be looked through page by page.
- [ ] The same pass on an iPhone simulator.

## 3. Release checks

Issue: [#163](https://github.com/Graphite-Note/Graphite/issues/163)

- [ ] `Docs/Release-checks.md`: what runs before each TestFlight upload, in order: the rule checks, the full Mac package suite, the full hosted suite, the vault pass of section 2 on the iPad and iPhone simulators, the size report, then the upload.
- [ ] `scripts/release-check.sh`, running those steps one at a time with the audio watch, stopping at the first failure that is not on the known list, and printing a summary to paste into the upload's What to Test.

## 4. The checks left for a device

Issue: [#165](https://github.com/Graphite-Note/Graphite/issues/165)

- [ ] Every open item of the todo files that waits only for "checked on the iPad / the Mac / with the owner's vault" is checked by a session with this vault: in the iPad and iPhone simulators (a session's own simulator) and in a copy of the Mac app with its own bundle identifier, with screenshots looked at, and on the owner's iPad for what needs Apple Pencil or the device's memory and speed. Each item checked is ticked in its own file with what was seen; one that needs the owner's own notes or a real Pencil gesture the session cannot make says so.

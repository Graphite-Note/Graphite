## Request

The owner, 2026-11-12: "id like to have a vault or whatever on the repo used to test every feature so we can have proper tests before releases". In the same message they asked that the checks left for a device or their vault be made by the sessions themselves, in a simulator or on their iPad, rather than left for the owner.

Today the repository has `Tests/BaseSampleVault` (36 files: bases, places, books, three course notes) for the bases, and each test writes its own small vault. No vault shows every feature at once, and nothing runs every kind of note through every view before an upload.

## 2. An automated pass over the vault

Issue: [#164](https://github.com/Graphite-Note/Graphite/issues/164)

- [ ] A Mac package test and an iPad hosted test that open every note of the vault in Live Preview, the reading view and source mode, and every other file in its own view, and fail on an error, a crash, a block left as raw source where a view was expected, a picture that did not load, or a main-thread freeze over a set budget.
  Built 2026-11-12, not yet seen green in its final form: `ReleaseVaultPass` with `ReleaseVaultPassTests` (Mac) and `ReleaseVaultPassHostedTests` (iPad and iPhone), three tests each, one per part of the vault (`ReleaseVaultPassPart`), run only with `GRAPHITE_RELEASE_PASS=1` (it takes minutes; it returns early otherwise, so the skip count does not rise). What it fails on is in Docs/Release-checks.md; the freeze budget is 1.5 s on the Mac and 2.5 s in the simulators. Runs: on the Mac, the pass as one test opened all 98 files in 263 s (631 screenshots, longest main-thread step 710 ms, opening the canvas) and found two mistakes of the vault (fixed) and the SVG gap (now `ReleaseVaultFinding.intended`); on the iPad simulator (iOS 27.2, Debug) the three parts took 52, 67 and 51 s (364 screenshots, longest step 824 ms), the first passed, and the others found the two defects now in Docs/Editor-scrolling-todo.md (kept as `isKnownOpenDefect`) and a web frame not loaded in time, since given WebKit's 40 s first start. Open: a run of the final version on the Mac and the iPad (the Mac's last two tries were stopped by audio from the owner's apps before any test; the iPad build of the last changes was not made).
- [x] Screenshots of every note in each view attached to the run (`XCTAttachment`, kept always), so a release candidate can be looked through page by page.
  Done 2026-11-12: every page of every view is an `XCTAttachment` kept always, named `<path> — <view> — page N`; on the Mac also written to `GRAPHITE_RELEASE_PASS_SCREENSHOTS`, at one pixel a point, with the PDF views' pages drawn in by PDFKit (`cacheDisplay` leaves them blank); `scripts/release-check.sh` exports the simulators' from the result bundles. Looked at: on the Mac, properties, callouts, the wide and mixed tables, the charts, the web frames loaded from the loopback server, the drawing, the bases' cards, the canvas, an SVG's own view; on the iPad, `Pictures.md` in its three views (where the two defects showed) and the web frames.
- [ ] The same pass on an iPhone simulator.
  Built 2026-11-12: `scripts/release-check.sh`'s `iphone-pass` step makes an iPhone (the newest iPhone Pro type, newest iOS runtime) with `xcrun simctl create`, runs `ReleaseVaultPassHostedTests` in it and deletes it; the window is the scene's own, so the phone's compact layout. Not run yet: the build slot was needed for another bug.

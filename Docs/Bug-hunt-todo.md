## How far to trust each item

Each item says how it was checked:

- **seen** (33): watched on an iPhone 17 Pro or iPad Pro 11-inch simulator, iOS 27.0, running this commit. Finger, not Pencil.
- **test** (16): a test calling the real function printed the wrong output. A sample of 20 logic findings was picked for this: 16 reproduced, 0 failed to, 4 could not run outside the UI or their own package. The tests are in the review file, so each can be flipped when its bug is fixed.
- **owner**: reported from the owner's own device.
- **traced**: read through in the code by a hunter, then by a second reader told to knock it down. Not run.
- **check**: the code path is real, but the outcome depends on SwiftUI, PencilKit or iCloud behaviour that code cannot show. The review's JSON names what to check.

Second readers rejected 21 hunter claims, and 30 duplicates were merged. Not covered: the Mac was only read, never run. No real iPad, iPhone or Apple Pencil was used. The owner's 31,748-file vault was not opened, so speed findings show the work done and its scale, not measured seconds. Calendar and reminders, link preview placement and image zoom were read and yielded nothing, and add-on resume was not checked. A drawing embedded in a note was not reached on the simulator.

## The owner's named complaints

- **Ink thicker when zoomed: HUNT-004.** Measured: a stroke drawn at about 3.3x zoom is about 2.7 times too thick on the page, permanently. The width appears to be applied twice. The test named for this only checks the tool's number, never a stroke. Needs one check with a real Pencil. Related: HUNT-012, HUNT-009, HUNT-019, HUNT-020, and HUNT-007 (the lasso cannot select such a stroke).
- **Blurry pictures: HUNT-001.** A picture keeps at most 2 pixels per page point of 60% of the page: a 4032x3024 photo becomes 715x536 on A4 and the original is not kept. Enlarging it gets worse (HUNT-010), and each rotate or crop loses more (HUNT-018).
- **Blurry ink: HUNT-003, HUNT-008.** Reported by the owner. The best trace is the canvas drawing at rounded zoom steps and at no more than 3x; a broad pencil lowers it for all ink on the page. Still needs a device comparison.
- **Tools not visible in portrait: HUNT-261.** In a split the tools and the pencil button vanish until the PDF side is tapped, because they follow focus. Also HUNT-264, HUNT-146, HUNT-265, HUNT-279, HUNT-262, HUNT-268, HUNT-289.
- **Settings opens on General: HUNT-237.** `SettingsView` starts with `selectedPage = .general`, on every platform.
- **Settings on iPhone: HUNT-237, HUNT-241.** General comes first and the list hides behind a small chevron; the list has no Done button, so only a swipe closes it. Every page walked did fit and scroll, so this is navigation, not layout. Sheets forced wider than a phone: HUNT-243, HUNT-271, HUNT-172.
- **"course-timetable Views Aren't Supported": HUNT-161.** Live Preview's block host never passes the plugin host to the embed, and the plugin is fine. Fixing that alone is not enough: HUNT-160, HUNT-169, HUNT-165, HUNT-166, HUNT-177. The message itself: HUNT-291.
- **Speed and loading: section 2.** Nothing shows but a spinner until the root folder is listed (HUNT-026), and any change anywhere lists it again (HUNT-027, HUNT-041).
- **Welcome tour pictures: HUNT-270.**

## Decisions for the owner

Second readers set these aside because the code or docs call them deliberate. They stay out of the counts until the owner says otherwise:

- A note's title shows `.md` twice (`Show File Extensions` on by default, and in the inline title). Obsidian hides it.
- A base reads at most 5,000 records and says so in a banner. Lifting the cap is a speed trade-off.
- Finger scrolling is blocked while the Pencil hovers over a PDF (documented in `Docs/Architecture.md`).
- `Format Code Blocks` is on by default; heading sizes differ from Obsidian's.
- ⌘W on the last tab (documented in `Docs/Architecture.md:156`).

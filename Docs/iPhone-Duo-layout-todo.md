# iPhone Duo layout

Request (decided 2026-10-21): get the app ready, layout-wise, for iPhone Duo, which Xcode 27.1 supports (iOS 27.1 SDK and a simulator for its poses and orientations). Apple's guidance is "Designing for iPhone Duo" in the Human Interface Guidelines.

Decisions:

- Graphite keeps one layout per size class. The outer display is a compact width (the phone layout) and the inner display a regular one. The system stands toolbars and the bottom bar on the side, and Graphite does not override where it puts them.
- On iOS a document's More commands go into the system's overflow menu, so the bar never shows two "•••" buttons. The Mac keeps its More menu.
- Graphite's own views follow a partly folded display through the system's division regions (iOS 27.1). The deployment target is iOS 27.0 ([OS-26-support-todo.md](OS-26-support-todo.md)), and the fold code does nothing before 27.1.

- [x] Decide what a single document does across the fold with the sidebar hidden (a note's reading column and a PDF page run across it today).
  Decided 2026-11-28: a single document keeps the whole display and runs across the fold, as it does today; nothing of it moves when the device folds. Apple's guidance for iPhone Duo asks apps not to reinvent their layout when the device changes pose and to move only what must stay visible and easy to tap ("Avoid extreme layout changes as people fold the device"), and it keeps the folding region away from controls and system components, not from scrolling content. What Graphite moves for the fold stays what section 1 built: the split's divider held on the fold, the palettes, the notice banner and the Read Aloud player beside it, and the library grid's even columns. A two-page view of a PDF on a book fold would be a new feature, not part of this layout work, and is not planned here.

# Running on macOS 26 (and why not iPadOS 26): TODO

Created: 2026-11-18.

Status: built on the branch `macos-26-support` 2026-11-18 and merged into `main` (f8d86359), with both deployment targets at 26.0. On 2026-11-27 the app and the hosted suite ran on an iPadOS 26.5 simulator, which found that iOS 26's PDFKit drops data at every save that Graphite's PDF features depend on (section 2). Decided the same day: the iOS and iPadOS deployment target is 27.0 again, and macOS keeps 26.0. The iOS 26 fallbacks and the tests' iOS 26 paths are removed. macOS 26 was not run, since this Mac runs macOS 27.2. Both sections are done. Issues: [#213](https://github.com/Graphite-Note/Graphite/issues/213) (section 1), [#261](https://github.com/Graphite-Note/Graphite/issues/261) (section 2).

## Request

Requested 2026-11-18: "i think we should also support macos26 as a lot of people are still on it", then iPadOS 26 as well, kept off `main` on a branch of its own ("do not push on main as that is a side quest").

Decided 2026-11-27, after section 2's finding: "Require iOS 27", with macOS staying at 26.0.

## What the result must be

- **The Mac app on 26 and 27.** Graphite installs and runs on macOS 26.0 and later, and on iOS and iPadOS 27.0 and later. It is still built with Xcode 27 and the 27 SDKs.
- **27 keeps what it has.** Each API macOS has only from 27 (or 26.1) sits behind `#available`; on 27 the code that runs is the code that ran before.
- **The compiler guards it.** With the macOS deployment target at 26.0, any new use of a macOS 27-only API fails to build until it has a fallback.

## Decisions

- Deployment targets: macOS 26.0 (`Package.swift`, `Packages/NotebookImport`, the Xcode project's four build configurations), not 26.1: 26.0 is the first release most people still on 26 have, and the one 26.1 API (`visibilityPriority` on the Mac) has a harmless fallback. iOS and iPadOS 27.0, since 2026-11-27 (section 2); from 2026-11-18 to then they were 26.0 too. `Packages/MermaidDiagrams`, a repository of its own, keeps iOS 26.0, which a 27.0 app may use.
- What macOS 26 shows instead, where 27's API has no older equal:
  - **Items kept in view (macOS 26.0).** `visibilityPriority(.high)` is macOS 26.1; before, those items fold like any other (`keptInViewWhenNarrow()`, `ToolbarFallbacks.swift`).
  - **Neural voice playback (macOS 26).** `connectNode(_:to:format:)` and `playAudio()` throw from 27; on 26 the engine uses `connect(_:to:format:)` and `play()`, whose failures raise an Objective-C exception instead of an error.
  - **Camera preview (macOS 26).** `sampleBufferReceiver(adding:)` is macOS 27; on macOS 26 the renderer is added to the synchronizer and frames are enqueued in it directly, flushing it first when it needs a flush to decode again.
- ~~What iOS 26 showed instead: a Library tile dragged alone (no drag containers), a More menu button of its own (no `ToolbarOverflowMenu`), items folded when the bar is narrow, and audio interruptions read from the interruption notification.~~ Removed 2026-11-27 with the iOS 27.0 target: `LibraryDragging.swift`, `ToolbarFallbacks.swift` (`MoreToolbarMenu` is gone), `AudioSessionInterruption.swift` and `PresentationSceneAccessory.swift` run the iOS 27 code alone.

## 2. PDFs saved on iPadOS 26

Issue: [#261](https://github.com/Graphite-Note/Graphite/issues/261)

Found 2026-11-27 by the hosted suite on an iOS 26.5 simulator: a small PDF with page labels, named destinations, viewer settings, a form, an outline, a link and another application's annotation, read by PDFKit and written again with no edit, comes out of iOS 26's PDFKit as PDF 1.3 without the catalog's `/PageLabels`, `/Names`, `/ViewerPreferences` and `/PageLayout` and without any annotation's `/NM`; macOS 27's PDFKit, writing the same file, keeps all of them. Graphite saves a PDF through PDFKit, and recognises its own pictures, text boxes, section links and ink by `/NM` (`PDFPicture`, `PDFTextBoxAnnotationReading`, `PDFMarkup`), so on iPadOS 26 a saved and reopened PDF loses those entries and Graphite's objects on it are no longer read as Graphite's.

- [x] Decide how iPadOS 26 handles PDF saving: restore what PDFKit drops after it writes (each annotation's `/NM` from the document in memory, the catalog's entries from the file read), raise the iOS and iPadOS deployment target to 27.0 while macOS keeps 26.0, or open PDFs read-only on iPadOS 26.
  Done 2026-11-27: "Require iOS 27". Restoring the dropped entries after every save would be a second writer behind PDFKit's, about 300 to 500 lines that every later PDF feature would have to keep in step with, and read-only PDFs would take away the iPad's main use. macOS 26's PDFKit was not checked, since no macOS 26 is at hand; the Mac package suite's PDF tests pass on macOS 27, whose PDFKit keeps every entry.
- [x] Build what is decided, with the ten hosted tests that fail on iOS 26.5 passing there or answered: `PDFObjectCompactionTests` (the saved catalog; a picture and a turned picture stored as their JPEG), `PDFAnnotationTests` (an outlined ink's `/NM`; ink removed by another application), `PDFPictureTests` (pictures of inserted pages), `PDFPageSharpnessHostedTests`, `PDFPageInkReadingTests` and `PDFInkOnTheDeviceHostedTests` (2). The dropped data is shown for the first five; the causes of the other five are not examined yet.
  Done 2026-11-27: `IPHONEOS_DEPLOYMENT_TARGET` 27.0 in the Xcode project's four configurations and `.iOS("27.0")` in `Package.swift` and `Packages/NotebookImport`; the iOS 26 fallbacks and tests' iOS 26 paths are removed (section 1, Decisions). The ten tests no longer run on iOS 26, which Graphite does not install on; they pass on iOS 27.2. Checked: the Graphite scheme builds for iOS and macOS, the changed hosted classes pass on an iPad Pro 11-inch (M5) simulator with iOS 27.2, rules and sizes.

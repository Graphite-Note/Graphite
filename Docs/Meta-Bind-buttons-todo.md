Created: 2026-11-26.

Status: 2026-11-26, built and checked in the Node tests, a dedicated iPad simulator and the Mac app. Taps by finger and clicks by hand were not made (no access to the simulator or the app was granted during the check). Four runtime gaps were fixed. 2026-11-27: the line of fields once drawn as code on the Mac was a race in drawing a block again, fixed, and the buttons and field were tapped by finger in the iPad simulator and clicked with the mouse on the Mac, which found a stale note after Back, fixed too. Issues: [#233](https://github.com/Graphite-Note/Graphite/issues/233) to [#237](https://github.com/Graphite-Note/Graphite/issues/237), one per section.

## Request

Feature 12 of `Docs/Notion-features-for-Graphite.md`: Notion's button blocks ("New assignment", "Start lecture" on a course page) through the Meta Bind community plugin (`obsidian-meta-bind-plugin`, by Moritz Jung, GPL-3.0), run unmodified in the plugin runtime. Its buttons are `meta-bind-button` code blocks and inline `` `BUTTON[id]` `` code, its input fields are inline `` `INPUT[…]` `` code, and its actions run commands, create notes from templates and set properties. Every gap that is the runtime's is fixed with a runtime test. What is Meta Bind's own is reported here.

## Decisions

1. **The release, not a build from source.** Meta Bind builds with Bun and Vite in a monorepo, unlike the npm plugins of `compatibility-plugins.json`. Its entry there pins release 1.5.1 (commit `8784bf7b`, 2026-06-16) and the SHA-256 of each release file (`main.js`, `manifest.json`, `styles.css`), the files Graphite's installer downloads from the same release. `npm run build-compatibility-plugins` downloads them and refuses a file whose checksum differs. Nothing of Meta Bind is committed.
2. **No native button syntax.** A Graphite syntax would be read by nothing else (`Docs/Notion-features-for-Graphite.md`, section 12). Meta Bind's code blocks are ordinary fenced code in the note, which Obsidian with Meta Bind draws the same way, and which any Markdown reader shows as code.
3. **Off costs nothing.** Meta Bind is a download: nothing of it is in the app, and with community plugins off its blocks stay code blocks.
4. **The demo vault is made up.** A small course, written for the demo, in `Tests/CommunityPluginRuntimeTests/fixtures/meta-bind-course-vault/`. No real notes.
5. **The demo's buttons are button templates.** Decided 2026-11-26: "New assignment" and "Start lecture" are Meta Bind's button templates, in its settings (`data.json`), not hidden `meta-bind-button` blocks of the course page. Meta Bind finds a hidden block's button only once the reading view has drawn the block, and a reading view draws only what is near the screen, in Obsidian too: in the Mac app, with the hidden blocks at the end of the page, the inline buttons said "Button ID not Found" when the page was drawn again. Templates are found at once, on any page.

  Done 2026-11-26: in Live Preview the inline fields and buttons stay code and the blocks are drawn, seen in the iPad simulator, and recorded in `Docs/Community-plugins.md` (What does not work yet, and Meta Bind's row).
- [x] Found 2026-11-26: once in five runs of the course page's hosted test on the Mac, the status line drawn again after the page was left and opened again came out as Graphite's own rendering, its fields as code, while its neighbours were Meta Bind's. Meta Bind reported no failure. Not reproduced in the Node tests or the iPad simulator, and the test then also scrolled the reading view while it was drawing. Find whether a section released while it is drawn is drawn again.
  Done 2026-11-27: the cause was Graphite's, a race in drawing a block again. The reading view draws a section or a code block again under the same identifier when its width changes (its `.task` is keyed by the request and the width's step, and on the Mac a scroll bar appearing changes it). The plugins' page then drops the earlier drawing, whose answer ("The section was closed while it was drawn.") could arrive after the newer drawing's, passed the check for the same request, and turned the block to failed, which a section shows as Graphite's own text. Each drawing now has a number, and only the newest one's answer is taken (`CommunityPluginShownCodeBlock.draw`, `drawingNumber`). `CommunityPluginRedrawnSectionTests` holds a plugin's first drawing until a second one of the same block has ended, then lets it answer: it failed with `failed("The section was closed while it was drawn.")` before the fix and passes after it. The course page's hosted test now changes the status field again after the page was opened again, the step that had failed: 15 of 15 runs passing on the Mac with the fix, and passing in the iPad simulator.
  Found while checking it on the Mac: when the test changed the status and pressed Start lecture within one second, Meta Bind ignored Templater's count of lectures (its write lock of five 200 ms cycles, logged in the page: its own write at 519 ms, Templater's at 1,327 ms with one cycle left) and later wrote its old count back. That is Meta Bind's design and the same in Obsidian. The test waits until Meta Bind takes changes again, as a person is slower.
